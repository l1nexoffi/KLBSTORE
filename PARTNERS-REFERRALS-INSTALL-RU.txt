KLB STORE — ПАРТНЁРЫ И РЕФЕРАЛЬНЫЕ ПРОМОКОДЫ

ФАЙЛЫ
- KLB_STORE_partner_referrals_update.zip — полный сайт + миграция + инструкция.
- KLB_STORE_marketplace_referral_partners.sql — миграция Supabase.
- KLB_STORE_marketplace_referral_partners.txt — тот же SQL в текстовом формате.
- KLB_STORE_partner_referrals_SQL.zip — только SQL и краткая инструкция.

ЧТО ДОБАВЛЕНО
1) В админ-панели появился раздел «Партнёры»: назначение пользователя по логину, тип партнёра (YouTuber, стример, блогер, инфлюенсер, автор контента, другое), включение и отключение статуса.
2) В разделе «Промокоды» появилась форма реферального промокода: логин партнёра, название промо, код, скидка покупателю (%), комиссия партнёру (%) и срок действия. Условия можно редактировать; код можно включать и отключать. Для одного партнёра одновременно действует один активный код.
3) В профиле активного партнёра появляется кнопка «Для партнёров». Кабинет показывает код, проценты, срок, количество использований, завершённые заказы, число покупателей, сумму фактических оплат, заработок по завершённым сделкам, фактически зачисленную на баланс сумму и непогашенный долг.
4) Комиссия партнёра начисляется только после подтверждения получения покупателем. При одобренном споре уже начисленная комиссия сторнируется. Невозмещённая часть учитывается как долг и удерживается из будущих партнёрских начислений.

ПРИМЕР
Цена товара: 1 000 ₽. Скидка покупателю: 5%. Комиссия партнёру: 5%.
- Покупатель оплачивает 950 ₽.
- Продавец получает 902,50 ₽ после комиссии KLB STORE 5% от фактически оплаченной суммы.
- Партнёру начисляется 50 ₽ (5% от исходных 1 000 ₽) после подтверждения сделки покупателем.

ВНИМАНИЕ ПО ЭКОНОМИКЕ
Партнёрская комиссия оплачивается отдельно из средств площадки. При комиссии партнёра, превышающей доход KLB STORE от сделки, маржа площадки может стать отрицательной. Выставляй ставки с учётом этого.

ПОРЯДОК УСТАНОВКИ
1. Сделай резервную копию Supabase.
2. Убедись, что ранее применены миграции кошелька, escrow/chat, управления аккаунтами и промокодов, а также жалоб/споров:
   - wallet-marketplace-migration.sql и wallet-frontend-support.sql;
   - marketplace-escrow-chat.sql;
   - klb-account-staff-telegram.sql;
   - marketplace-promo-redemption.sql;
   - marketplace-trust-safety.sql.
   Если используется новый каталог и продвижение, должна быть применена и marketplace-categories-promotions.sql.
3. Открой Supabase → SQL Editor → New query.
4. Открой KLB_STORE_marketplace_referral_partners.txt в Блокноте, скопируй весь текст и нажми Run в SQL Editor.
5. Распакуй ZIP и загрузи содержимое папки klb_full в корень GitHub Pages с заменой файлов.
6. Сохрани свой существующий supabase-config.js — не заменяй его примером.
7. Дождись публикации GitHub Pages и обнови сайт Ctrl+F5.

Старые миграции повторно запускать не нужно. Эта новая миграция не удаляет пользователей, товары, кошельки, заказы или историю операций. Она добавляет таблицы партнёров/начислений, поля для реферальных кодов и обновляет серверные RPC покупок, подтверждения и споров.

ПРОВЕРКА ПОСЛЕ УСТАНОВКИ
1. В админке → Партнёры назначь тестового партнёра по логину.
2. В Промокодах создай реферальный код (например, скидка 5%, комиссия 5%).
3. На тестовом покупателе активируй код, купи товар за 1 000 ₽, затем подтверди выполнение со стороны продавца и получение со стороны покупателя.
4. Проверь: покупатель оплатил 950 ₽; продавцу начислено 902,50 ₽; партнёру начислено 50 ₽.
5. На тестовой завершённой сделке проверь одобрение спора и сторнирование партнёрской комиссии.

SQL проверен статически и не запускался в твоём реальном проекте Supabase. Сначала тестируй на двух тестовых аккаунтах и небольших суммах.
