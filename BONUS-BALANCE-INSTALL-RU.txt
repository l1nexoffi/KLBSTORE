KLB STORE — БОНУСНЫЙ БАЛАНС

ЧТО ДОБАВЛЕНО
1. В админке → Пользователи появилась кнопка «Начислить бонус».
2. Администратор вводит сумму и причину (например, «Приз конкурса»).
3. Начисление записывается в кошелёк и историю с ID администратора.
4. У пользователя бонус показывается отдельно от обычного баланса.
5. Бонус нельзя вывести: заявка на вывод продолжает списывать только обычный balance.
6. При покупке сначала расходуются бонусы, потом обычные деньги.
7. При одобренном споре возврат возвращается в те же корзины, из которых была оплачена покупка.

УСТАНОВКА
1. Сделай резервную копию Supabase.
2. Открой Supabase → SQL Editor → New query.
3. Выполни marketplace-bonus-balance.sql (в ZIP он лежит в корне klb_full).
4. Распакуй ZIP сайта.
5. Замени файлы GitHub Pages содержимым klb_full.
6. Не заменяй свой supabase-config.js.
7. Дождись публикации GitHub Pages и обнови сайт Ctrl+F5.

ВАЖНО
- Новая миграция рассчитана на уже установленную текущую схему KLB STORE: кошелёк, marketplace escrow, промокоды, trust/safety и referral partners.
- Старые SQL повторно запускать не надо.
- SQL не удаляет пользователей, заказы, кошельки и историю.
- Бонусы разрешено тратить на оплату товаров/услуг в каталоге. Они не включаются в withdrawable available и не могут быть выведены через заявки на вывод.
- Checkout использует бонусный остаток в первую очередь, затем обычный доступный баланс.
- В заказ записывается разбивка источников оплаты; если спор одобряется, каждому источнику возвращается его собственная часть.
- Сначала протестируй на тестовом пользователе: начисли 500 ₽ бонуса, попробуй вывести, затем купи недорогой товар. Вывод не должен включать бонус, покупка должна использовать бонус первым.
