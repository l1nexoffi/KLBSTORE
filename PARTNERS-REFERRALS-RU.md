# KLB STORE — партнёры и реферальные промокоды

## Возможности

### Администратор
- В админ-панели появился раздел **Партнёры**.
- Назначение партнёра по логину пользователя.
- Тип партнёра: YouTuber, стример, блогер, инфлюенсер, автор контента или другое. Тип — только метка; финансовые условия одинаковы.
- Отключение и повторное включение партнёрского статуса.
- В разделе **Промокоды** появилась отдельная форма реферального промокода: логин партнёра, название, код, скидка покупателю, комиссия партнёру и дата окончания.
- Условия созданного кода можно редактировать; код можно включать и отключать.
- На одного партнёра действует один активный реферальный код одновременно.

### Партнёр
После назначения партнёра в его профиле появляется кнопка **Для партнёров**. Кабинет показывает код, скидку, комиссию, дату окончания, количество использований, завершённые заказы, количество покупателей, сумму оплаченных ими заказов, начисления и возможный долг после возврата по спору.

### Покупка и начисление
- Покупатель активирует промокод в профиле.
- При оплате скидка уменьшает сумму покупателя.
- Партнёрская комиссия рассчитывается от исходной суммы заказа **до скидки**.
- Комиссия не начисляется при самом оформлении заказа. Она поступает в баланс партнёра только после подтверждения покупателем получения товара/услуги.
- Если позже одобрен спор по уже завершённой сделке, партнёрская комиссия сторнируется. Доступные средства списываются; недостающая сумма учитывается как долг и удерживается из следующих партнёрских начислений.

## Пример расчёта
Товар стоит 1 000 ₽. Скидка покупателю — 5%, комиссия партнёру — 5%.
- Покупатель платит 950 ₽.
- Партнёру начисляется 50 ₽ после завершения сделки.
- Стандартная комиссия KLB STORE 5% рассчитывается с суммы, которую оплатил покупатель (47,50 ₽), а выплата продавцу составляет 902,50 ₽.

Партнёрская комиссия выплачивается отдельно из средств площадки. При установке процента партнёра выше дохода площадки по сделке реальная маржа KLB STORE может стать отрицательной. Устанавливайте ставки с учётом этого.

## Установка
1. Сделайте резервную копию Supabase.
2. Убедитесь, что до этого применены миграции кошелька, escrow/chat, промокодов и жалоб/споров:
   - `wallet-marketplace-migration.sql`;
   - `marketplace-escrow-chat.sql`;
   - `klb-account-staff-telegram.sql`;
   - `marketplace-promo-redemption.sql`;
   - `marketplace-trust-safety.sql`.
3. Если используется новый каталог, до партнёрской миграции также должна быть применена `marketplace-categories-promotions.sql`.
4. Откройте Supabase → SQL Editor → New query.
5. Скопируйте весь `marketplace-referral-partners.sql` и нажмите Run.
6. Распакуйте ZIP и загрузите содержимое папки `klb_full` в корень GitHub Pages.
7. Сохраните действующий `supabase-config.js`; не заменяйте его примером.
8. Дождитесь публикации GitHub Pages и обновите сайт.

Новая миграция дополняет существующую схему и не удаляет пользователей, товары, кошельки, заказы или историю. Старые миграции повторно запускать не нужно.

## Рекомендуемая проверка
1. Назначить тестового партнёра.
2. Создать для него реферальный код, например 5% скидки и 5% комиссии.
3. Активировать код на тестовом покупательском аккаунте.
4. Купить товар за 1 000 ₽.
5. Продавец подтверждает выполнение, покупатель подтверждает получение.
6. Проверить начисление 50 ₽ партнёру и 902,50 ₽ продавцу (при комиссии KLB STORE 5% от фактически оплаченных 950 ₽).
7. Проверить, что отмена/одобрение спора после выплаты сторнирует партнёрское начисление.

SQL подготовлен для указанной схемы KLB STORE, но не был выполнен в вашем проекте Supabase. Перед рабочими продажами обязательно протестируйте цикл на тестовых аккаунтах.
